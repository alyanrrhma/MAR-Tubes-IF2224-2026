# Milestone 2 Tugas Besar IF2224 - Teori Bahasa Formal dan Automata : Syntax Analysis

## Description
This project is an implementation of a **Syntax Analyzer (Parser)** for the **Arion programming language** as part of **Milestone 2 - IF2240 Formal Language and Automata Theory**. The parser is the second phase of compilation, responsible for validating the syntactic structure of source code based on the grammar rules of the language.

The program is implemented in **C/C++ GNU** and uses a **Recursive Descent Parser** approach to process tokens generated by the lexer. The parser reads the token stream sequentially, validates the grammar structure, and constructs a **Parse Tree** representing the hierarchical structure of the source program.

This milestone extends the previous lexical analyzer implementation by adding syntax analysis and parse tree generation.

The parser is designed to recognize:
- program structure
- declarations
- variables and constants
- array and record types
- procedures and functions
- expressions
- assignment statements
- conditional statements
- looping statements
- procedure/function calls

The implementation is developed in a **modular structure** to support future milestones such as semantic analysis and code generation.

## Parser Features

The parser supports:
- Recursive Descent Parsing
- Parse tree generation
- Syntax validation
- Error handling with informative messages
- Compound statements (`begin-end`)
- Expressions and operators
- Conditional statements (`if`, `case`)
- Looping statements (`while`, `repeat`, `for`)
- Procedures and functions
- Arrays and records

### Index-list extension

The Milestone 2 grammar defines index-list using intcon, charcon, or ident.
This implementation intentionally extends index-list to accept full expressions,
such as `a[i + 1]`, to support more practical array indexing in later
milestones. This is an implementation extension and does not change the
required basic behavior.

### Revision compliance for `while` and `for`

The parser now follows the later revision used for Milestone 2/3 continuity: `while` and `for` bodies must be `compound-statement` blocks. Therefore `while x < 10 do x := x + 1;` is rejected, while `while x < 10 do begin x := x + 1; end;` is accepted. This makes the implementation consistent with the revised grammar and prevents ambiguous loop-body parsing.

## How To Run

To run only the parser milestone from Arion source code, execute:

```bash
./bin/arion <program.txt> --parse-only --save-parse-tree <parse-tree.txt>
```

To run the parser from Milestone 1 token output instead of source code, execute:

```bash
./bin/arion --from-tokens <tokens.txt> --parse-only --save-parse-tree <parse-tree.txt>
```

### Example

```bash
make all
./bin/arion test/milestone2/input/input21.txt \
  --parse-only \
  --save-parse-tree test/milestone2/output/parse_tree21.txt
```

To run lexical analysis only:

```bash
./bin/arion test/milestone2/input/input1.txt --lex-only -o test/milestone2/output/token1.txt
```

### Additional Options

| Option | Description |
|---|---|
| `--parse-only` | Stop after syntax analysis; this avoids semantic/backend stages during Milestone 2 grading |
| `--from-tokens <file>` | Read Milestone 1 token output and parse it directly |
| `--save-tokens <file>` | Save token output |
| `--save-parse-tree <file>` | Save parse tree output |
| `--save-ast <file>` | Save decorated AST output |
| `--verbose` | Print tokens, parse tree, and decorated AST to stdout |
| `--lex-only` | Run lexer only without parser |
| `-o <file>` | Output file; with `--lex-only` saves tokens, with `--parse-only` saves parse tree, otherwise saves AST |
